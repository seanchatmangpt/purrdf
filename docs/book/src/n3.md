# Notation3 (N3): parsing, reasoning and proofs

[`purrdf-n3`](https://docs.rs/purrdf-n3) is native, wasm-clean Notation3: a
parser for N3's superset of Turtle — graph formulas `{ … }`,
`@forAll`/`@forSome` quantification, `=`/`<=`/`=>` paths and the `log:`
vocabulary — plus semi-naive forward reasoning over formula-scoped rule sets
and backward, proof-carrying chains.

It is the parser and prover beneath [`purrdf-entail`](entailment.md)'s N3
surface, and is published separately so a caller can depend on N3 alone.
Note that it is *not* re-exported by the umbrella `purrdf` crate; depend on
`purrdf-n3` directly.

## Formula-scoped model

`@forAll`/`@forSome` bind within their enclosing formula scope; a universal
that escapes its scope is a parse-time refusal, not a silent capture
(`crates/n3/src/parser.rs`). Triple terms keep the RDF 1.2 term model exactly;
a formula term is a first-class term identity of its own. `log:` predicates
are parsed as ordinary IRIs — the *meaning* of `log:implies` and friends is
supplied by the reasoner, not the parser: a formula with unparsed `log:`
payloads still round-trips as data.

Design commitments, shared with [`Datalog`](datalog.md):

- **One term identity across scopes.** Every term — literal, IRI, blank node,
  formula — is minted through the shared interner, so a term quoted inside
  `{ … }` and the same term asserted at the top level are one identity, and
  scope is a property of the rule set, never of the term.
- **Reasoning is semi-naive over scoped rules.** Rule bodies that span formula
  boundaries lower onto the same ordered schedule the Datalog evaluator runs;
  no second evaluator is minted for N3.
- **Proofs are backward and content-addressed.** A backward chain from a goal
  carries the same derivation-identity recipe the reasoning lane keys on, so a
  proof can be replayed and checked independently of the forward closure.
- **Deterministic by construction.** Fixed-key hashing (`FixedHasher`, not
  `RandomState`), insertion-ordered per-key rows, and no map iteration order
  on an output path. Identical input yields byte-identical output on every
  target.
- **Limits refuse; they never truncate.** Any budget is the caller's and can
  only produce a typed refusal naming the limit — never a partial parse or a
  truncated model.
- **No optionality.** No Cargo feature flags; no conditional compilation
  selecting between semantics.

## Public API surface

The facade is `crates/n3/src/lib.rs`: it re-exports the public API at the
root so callers depend on one stable surface, not on module paths.

### Parsing

```rust
use purrdf_n3::{parse_n3, parse_n3_with_source, Document};

// Parse one N3 document (Turtle-compatible, plus formulas and rules).
let doc: Document = parse_n3(input, None)?;
```

`parse_n3(input, base)` accepts N3's superset of Turtle: formulas `{ … }`,
`@forAll`/`@forSome`, `=`/`<=`/`=>`, and `@prefix`/`@base` resolution through
the workspace's one IRI-resolution spelling. `parse_n3_with_source` attaches
a source label used in diagnostics. The parser also reads what N3 reasoning
consumes: Turtle, TriG, N-Triples, N-Quads and RDF Message Logs
(`is_rdf_message_log` / `parse_rdf_message_log`).

### One-call reasoning

```rust
use purrdf_n3::reason;

// Parse, run the forward reasoner, and print newly-derived triples as N3.
let out: String = reason(input)?;
```

`reason` is the convenience entry point: it parses (auto-detecting RDF
message logs), runs forward reasoning with `include_explicit: false`, and
renders only the newly-derived triples via `result_to_string`. If the run
hits a limit, the typed summary becomes an `Err` — limits refuse, they never
truncate.

### Prepared programs

```rust
use purrdf_n3::{parse_n3, PreparedReasoner, ReasonerOptions};

let program = parse_n3(rules_text, None)?;
let prepared = PreparedReasoner::new(program);
for data in &data_documents {
    let result = prepared.reason(data, &ReasonerOptions::default());
    // `result.derived` holds this batch's newly-derived facts only.
}
```

`PreparedReasoner::new(program)` builds the forward agenda and splits query
rules from active rules once; each `prepared.reason(&data, &options)` call
runs one independent data document against the shared program. Facts derived
by one call are not retained for the next — data batches are independent by
construction, so a static rule set is prepared once and reused. (When holding
both, note `reason_document` is the re-exported module-level `reason` over a
`Document`; the crate-root `reason(&str)` is the parse-plus-run convenience.)

### Reasoner options and results

`ReasonerOptions` bounds the whole run in caller-owned budgets:
`max_iterations` (fixpoint steps), `max_match_steps`, `max_backward_depth`,
`max_backward_solutions_per_goal`, `max_term_bytes`, `max_total_bytes`,
`max_closure_facts`, `max_total_steps`, plus `trace`, `proof` and
`include_explicit` switches. A budget exhausted yields
`ReasonerResult::incomplete_summary()` — a typed summary, not a partial
closure presented as complete.

A `ReasonerResult` carries `.derived` (newly-derived facts),
`.explicit`/`.explicit_sources` (the input copy, needed for proof
reconstruction; forced on whenever `proof` is set), fused rules
(`FiredFuse`), statistics, and `CompletionStatus`.

### Proofs

```rust
use purrdf_n3::{parse_n3, proof_to_n3, reason_document, ReasonerOptions};

let doc = parse_n3(input, None)?;
let mut options = ReasonerOptions { proof: true, ..ReasonerOptions::default() };
let result = reason_document(&doc, &options);
let proof_text = proof_to_n3(&doc.prefixes, &result);
```

`proof_to_n3` renders an N3 proof document for what the run derived, recording
only the steps those claims depend on. The proof is checked independently by
the reference checker (`proof_check`) and its N3 reader (`proof_check_n3`), so
a proof can be replayed without the forward closure. Backward explanation is
available through `explain_backward` and `find_backward_proof_for_goal`.

## Lossless bridge to RDF 1.2 terms

The N3 AST keeps the RDF 1.2 term model exactly: IRIs, blank nodes, literals
with datatype and language, plus N3-only terms (variables and formulas) as
first-class identities. The `rdf_compat` module (declared in the facade,
`crates/n3/src/lib.rs`) is the bridge to the codecs' term identities minted
by `purrdf-rdf`: the parser lowers N3's `@prefix`/`@base` resolution onto the
same relative-reference resolution the other codecs use, and triples parsed
from Turtle/TriG/N-Triples/N-Quads lower onto the same term and triple
constructors, so an N3 formula and a codec-minted dataset share term identity
— never a second spelling.

## Wasm story

`purrdf-n3` is wasm-clean by construction: no filesystem, no clock, no RNG,
and fixed-key hashing because `wasm32` has no entropy source and iteration
order must never reach an output path. Identical input yields byte-identical
output on every target — the same artifact runs on host and wasm. Consistent
with the workspace's no-features law, the crate carries no Cargo feature
flags and no conditional compilation selecting between semantics.

See [`Entailment`](entailment.md) for the RDF/RDFS/OWL 2 RL/D calculi declared
as programs over this surface, and [`Datalog`](datalog.md) for the fixpoint
engine those calculi evaluate on.
