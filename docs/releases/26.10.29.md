# PurRDF 26.10.29

PurRDF 26.10.29 introduces the process-mining and planning layer and completes the
knowledge-hooks onboarding.

- New `purrdf-process` crate: POWL 2.0 models (validated ASTs, bounded language
  semantics, workflow-net soundness, PartitionMG/PartitionSM decomposition),
  OCEL 2.0 event logs (dual-dialect JSON/NDJSON ingestion, referential
  validation, canonical ids, deterministic writer, BLAKE3 integrity chains),
  HTN/FOND synthesis (policy validation and synthesis with typed refusals,
  witness states, counterexample classes, receipts), and the conformance
  turnstile (pm4py-convention token replay with a u64-bitmask fast path,
  polynomial order-preserving shuffle membership, deterministic A\*
  alignment) — one engine over `purrdf-hash`/`purrdf-lex`/`purrdf-xsd`/
  `purrdf-branchless`, FastState-map determinism throughout.
- The facade re-exports the new surface as `purrdf::process`.
- Workflow-net soundness reports every property (bounded, 1-safe, final
  reached, one final marking, no dead transitions, option to complete,
  deadlock-free) — nothing is silently skipped.
- Layering and version coherence carry the new crates; the registry-publish
  concern is retired entirely — this fork is consumed via git reference, every
  member manifest carries `publish = false`, and the release lane is empty by
  design.

This release jumps the workspace from the 3.x line to the date-versioned
26.10.29, aligning PurRDF's version scheme with the rest of the ecosystem.
The next step is `make bump`-style version propagation: the workspace version
is single-sourced in `[workspace.package]`, so the jump is a manifest-level
change with no API break beyond what 4.0 was already carrying.
